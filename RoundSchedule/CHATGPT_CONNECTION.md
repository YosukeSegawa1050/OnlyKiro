# ChatGPTから予定を閲覧・編集する

Daily Schedule 2.2.0の共有接続手順です。予定表とChatGPTが同じSQLiteデータを使い、個人1人の予定の一覧・検索・追加・編集・削除に対応します。公開先は未定のため、HTTPS公開と利用者自身のChatGPTでの登録は未実施です。

## このPCで起動

Node.js 24以降を使用します。

```powershell
npm.cmd ci --ignore-scripts
npm.cmd run setup:shared
npm.cmd run start:shared
```

`setup:shared` は `.env` にランダムなパスフレーズを生成します。既存の `.env` は上書きしません。パスフレーズをログには表示しません。ログイン時はこのファイルの `SCHEDULE_PASSPHRASE` を参照してください。`.env` と実データはGit・Dockerの送信対象から除外しています。

既定のURLは http://127.0.0.1:8765/RoundSchedule.html です。既存の静的サーバー `npm.cmd start` がこのポートを使用している場合は、そちらを終了してから共有サーバーを起動します。

1. 予定表の「ChatGPT連携」を開き、共有用パスフレーズでログインします。
2. 「この端末の予定を共有」を選びます。表示された予定・カテゴリー・テンプレートをサーバーへ保存します。元の端末内データも残ります。
3. すでに共有先が設定済みの場合は「共有予定を開く」で切り替えます。端末内データで共有予定を上書きすることはありません。
4. 接続後はアプリでの保存が共有先へ反映され、他の画面やChatGPTの変更を約5秒ごと・画面復帰時に取得します。

**元の予定表と同じブラウザー・URLのorigin（スキーム・ホスト・ポート）を使用してください。** `localhost` と `127.0.0.1` は別の保存先です。以前の公開サイトから別ドメインへ移る場合は、元の画面の「設定・データ」で「バックアップ JSON」を選び「保存」、新しい画面でも同じ形式を選び「読込」してから共有します。別originのIndexedDBは自動では読み出せません。

パスフレーズによるアプリのログインと、ChatGPTへのアクセス許可は別です。アプリにログインしただけではChatGPTへ予定は送信されません。

## 公開先が決まったら

Node.jsを常時実行できるサーバーまたはDocker環境と、SQLiteを保存する永続ディスクを使います。静的ファイルのみの配信や、実行ごとにディスクが消える関数環境にはそのまま配置できません。既存のVercel静的設定はローカル版の配信に引き続き使用できます。

必要な環境変数:

| 変数                           | 値                                                                |
| ------------------------------ | ----------------------------------------------------------------- |
| `SCHEDULE_BASE_URL`            | パスを含まない公開HTTPS origin。例 `https://schedule.example.com` |
| `SCHEDULE_PASSPHRASE`          | 20〜1024文字。`setup:shared`は十分長いランダム値を生成            |
| `SCHEDULE_DATA_DIR`            | 永続ディスク上の保存先。既定 `.schedule-data`                     |
| `SCHEDULE_TIME_ZONE`           | 予定のタイムゾーン。既定 `Asia/Tokyo`                             |
| `HOST`                         | 外部のリバースプロキシから受ける場合 `0.0.0.0`                    |
| `PORT`                         | Nodeサーバーの待受ポート                                          |
| `SCHEDULE_OAUTH_REDIRECT_URIS` | 必要な場合だけ追加callback URLのJSON配列。完全一致                |

Dockerfileを同梱しています。TLSは配置先のHTTPS終端で設定し、元のHostヘッダーを保持します。`.env`をイメージへ埋め込まず、配置先から環境変数として注入してください。

```text
docker build -t round-schedule .
docker run --env-file .env.production -e HOST=0.0.0.0 -e PORT=8787 -p 127.0.0.1:8787:8787 -v round-schedule-data:/app/.schedule-data round-schedule
```

`.env.production` は公開環境の設定を用意する例です。`SCHEDULE_DATA_DIR=/app/.schedule-data`、`SCHEDULE_BASE_URL=https://...` を設定してください。コンテナー内の8787へHTTPSプロキシを接続します。Dockerイメージのビルド・公開環境への配置は未検証です。

データは `schedule.sqlite` とWALに保存されます。バックアップはアプリのJSON書出、またはサーバー停止後の保存ディレクトリー全体の複製を使います。JSONは予定データのバックアップで、OAuth接続情報は含みません。

## ChatGPTで接続

1. HTTPS公開した予定表へログインし、予定を共有状態にします。
2. 予定表の「ChatGPT連携」→「ChatGPTの接続設定」を開き、接続URL `https://.../mcp` をコピーします。ChatGPTの開発者モードでMCP接続を追加して登録します。利用可否はアカウント・ワークスペースの設定によります。
3. OAuth認証を使用します。このサーバーは動的クライアント登録（DCR）に対応するため、固定のclient secretやOpenAI APIキーは不要です。
4. 表示される承認画面でサーバーのパスフレーズを入力し、予定へのアクセスを許可します。
5. 新しいチャットで接続を有効にして、下記の操作を試します。

接続UIは更新されるため、実際の登録手順は[OpenAIの接続ガイド](https://developers.openai.com/plugins/deploy/connect-chatgpt)を参照してください。公式の[認証仕様](https://developers.openai.com/plugins/build/auth)に従い、PKCE S256・resource照合・issuer識別を実装しています。既定のcallbackは `https://chatgpt.com/connector_platform_oauth_redirect` です。ChatGPTの管理画面に別のcallbackが表示された場合は、その完全なURLを追加allowlistへ設定します。

試す会話の例:

- 「2026年9月10日の予定を見せて」
- 「2026年9月10日14時から15時に、仕事カテゴリーで打ち合わせを追加して」
- 「その打ち合わせを16時から17時へ移して」
- 「毎週の勉強の予定のうち、9月15日の回だけ18時からに変更して」
- 「今追加した打ち合わせを削除して」

実際の登録・公開前はローカルアドレスをChatGPTに貼るだけでは接続できません。今回の検証はローカルHTTP、ブラウザー、公式MCP SDKクライアントで行い、実ChatGPTのアカウント内操作は含みません。

## 保存と編集の動作

- サーバー側でも既存の日時・繰り返し・重複判定を利用します。既存データの重複は初回取込時に保持し、追加・時間変更による新しい重複を拒否します。
- アプリの書込とChatGPTからの更新・削除はrevisionを照合します。競合時は入力を残し、最新の予定を確認してからやり直します。
- 書込の通信再試行は同じ操作IDを使い、二重登録を防ぎます。処理済みの操作IDはサーバー再起動後も保持します。
- 保存結果が不明な操作は端末にも記録します。次の保存ではその操作の結果を先に確認し、新しい操作を重ねて実行しません。保存済みと案内された場合は入力を閉じ、一覧の予定を開いて確認してください。
- 繰り返しの更新・削除は「この回のみ」か「全体」の指定が必要です。「この回のみ」は指定回を除外し、変更後の単発予定を保存します。
- 共有モードの通信切断・ログイン期限切れは、保存済みの控えを閲覧できます。接続できない状態で端末内だけに予定を書き込むことはありません。端末保存モードは従来どおりオフラインで編集できます。
- 共有予定の時刻は設定したタイムゾーンです。端末のタイムゾーンが違う場合は閲覧のみとし、編集・取り消し・通知を止めます。
- 別タブで保存先を切り替えた場合は、古い保存先へ書き込まず再読み込みを案内します。サーバーDBのバックアップ復元でrevisionが戻った場合も閲覧のみとし、「ChatGPT連携」の「再読み込み」で明示的に取得し直します。
- アプリの「元に戻す」は、共有先の直前操作にも使えます。未確認の更新があれば拒否します。共有先は最大30操作を保持します。
- 「端末内へ切り替え」を開き「保存して切り替え」を選ぶと、最新の共有予定を端末へ保存します。元の端末データも復元前バックアップに残します。ChatGPTのアクセス許可は継続します。
- 「アクセス許可」にある接続の「解除」でChatGPTのアクセスを止められます。解除済み・期限切れのトークンは、次のリクエストから拒否します。アプリからのログアウトはChatGPTの許可解除とは別です。
- 共有サーバー追加後も、アプリ終了後の定刻通知を送るWeb Push配信は未実装です。

## 実装の入口

| ファイル            | 役割                                                                 |
| ------------------- | -------------------------------------------------------------------- |
| `shared-storage.js` | 共有Repository、版照合、再試行、閲覧用キャッシュ、端末保存からの切替 |
| `shared-ui.js`      | ログイン、共有開始、接続URL、許可済み接続の解除                      |
| `server/store.cjs`  | SQLiteトランザクション・履歴・操作ID                                 |
| `server/auth.cjs`   | アプリsession、OAuth、PKCE、権限・期限・解除                         |
| `server/mcp.cjs`    | 予定一覧・取得・追加・更新・削除のMCPツール                          |
| `server/http.cjs`   | APIとMCPの認証付き配信、静的資産の限定配信                           |
| `server/start.cjs`  | サーバー起動と終了                                                   |

検証は `npm.cmd run check`、`npm.cmd run format:check`、`npm.cmd test`、`npm.cmd run build` で実行できます。
