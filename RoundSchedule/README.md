**Daily Schedule 2.0.0**

24時間の円グラフと予定一覧を組み合わせた、端末内で使うスケジューラーです。実行時の外部ライブラリー、外部フォント、外部CSSへの通信はありません。

**起動・検証**

Node.js 24で検証しています。プロジェクトのディレクトリーで以下を実行します。Windows PowerShellでnpm.ps1が制限されている場合はnpm.cmdを使います。

```text
npm.cmd ci --ignore-scripts
npm.cmd run check
npm.cmd run format:check
npm.cmd test
npm.cmd run build
npm.cmd start
```

ブラウザーで http://127.0.0.1:8765/RoundSchedule.html を開きます。終了は起動したターミナルでCtrl+C。ファイルを直接ダブルクリックする方法は、PWA・通知・保存の動作を揃えられないため検証対象外です。

本番はHTTPSでdistの静的ファイルを配信します。buildは必要な12ファイルだけをdistへコピーします。vercel.jsonのルート書き換えを維持し、buildCommandとoutputDirectoryを指定しています。開発用サーバーもプロダクトのファイルのみ配信し、テスト・依存ファイル・レビュー文書を公開しません。

**日時と予定の仕様**

- 予定は開始日・開始時刻・終了日・終了時刻を持ちます。23:00〜翌06:00は終了日を翌日に指定します。
- 表示・重複・集計・繰り返しは同じ日時処理を使います。日をまたぐ予定は各日の範囲へ切り取って表示し、一覧には継続であることを示します。
- 区間は開始を含み終了を含みません。09:00〜10:00と10:00〜11:00は重複しません。
- 時間指定予定は7日以内。開始と終了が同じ日時の予定は登録しません。
- 終日は開始日〜終了日を両端含みます。時刻未定は開始日だけに表示します。終日・時刻未定は時間指定予定を妨げない情報として扱います。
- 完了した時間指定予定も一日の時間を使ったものとして集計。中止予定は時間の占有と通知の対象外です。
- 繰り返しは曜日指定、終了日を含む1年以内。この回のみの変更は元のシリーズへ除外日を追加し、単発予定を作成します。全体の変更は最初の開始日から適用します。
- テンプレートには対象日に開始する予定を保存します。前日からの持ち越しは含みません。置換時も前日開始の予定は残し、衝突時には全体を適用せずエラーにします。
- 時刻は端末の現地時刻です。端末のタイムゾーンを変更すると通知の実時刻も変わります。固定タイムゾーンの予定、夏時間の欠落・重複時刻の専用UIは未対応です。

**保存と移行**

- 新しい保存先はIndexedDBのdaily-schedule-v2です。読込・競合確認・書込・取り消し用退避を同じトランザクションで行います。
- localStorageのdaily_schedule_dataがある場合、初回だけ検証して移行します。旧データの原文を退避し、元のlocalStorageは削除しません。旧データに日付がなければ移行日を割り当て、結果を永続化します。
- 構造が壊れたデータは黙って初期化しません。原文の保存、正常項目の確認付き復旧、JSONバックアップからの復旧を案内します。
- JSON復元は件数を表示して確認後に実行。直前の全データを別途退避し、「元に戻す」も用意します。
- Undoは直前の保存操作1回分です。別タブの未確認の更新がある場合は拒否します。変更履歴を無制限に保持する機能ではありません。
- 編集中の予定・カテゴリー・テンプレートが別タブで変更された場合、古い編集で上書きせず入力を保持して知らせます。
- 予定の下書きはsessionStorageに保存します。同じタブでの再読込・閉じた編集画面からの復帰に対応し、7日以内の下書きを復元できます。ブラウザー全体の終了後までの保持は保証しません。
- 移行後は旧バージョンのタブを閉じてください。旧タブでlocalStorageが更新された場合は案内を表示します。IndexedDBのデータを旧版へ自動的に戻す処理はありません。
- ブラウザーの全データ削除に備え、ダウンロードしたJSONを別の場所に保管してください。端末間の自動同期はありません。

**通知・オフライン・出力**

- 通知は明示的な操作で許可し、設定を保存して有効化します。開始時・1/5/10/15/30/60分前を全体設定で選択できます。予定ごとの上書きもあります。
- 発火時刻は秒を含む絶対時刻で計算し、日付境界にも対応。通知済みキーをIndexedDBで取得してタブ間の重複を抑えます。失敗時は再試行できるようキーを戻します。
- アプリ終了後の予約実行やバックグラウンドでの定刻配信は保証しません。遅れた通知は1分以内のものだけを扱います。Web Push配信サーバーは未実装です。
- モバイルではService WorkerのshowNotificationを優先します。通知を選ぶと該当日の予定を開き、他の編集中の画面を移動させません。
- SWはバージョン単位でHTML/CSS/JSをまとめて事前保存し、その組み合わせで起動します。キャッシュ済みなら低速回線や503でもネットワークを待ちません。
- 更新はボタンから取得・有効化し、下書きを保存してから再読込します。他アプリのキャッシュを削除したり、他アプリのページ遷移を置き換えたりしません。
- ICS出力は指定した1年以内の期間の繰り返しを単発予定に展開します。ICS入力は単発VEVENT、分単位の日時ありまたは終日、現地時刻またはUTCに対応。RRULE、RECURRENCE-ID、EXDATE、TZIDや秒単位の時刻を含む入力は説明付きで拒否します。
- SVG画像として一日を保存できます。印刷ボタンからブラウザーの「PDFに保存」も利用できます。Google/Apple等のカレンダーとの双方向同期ではありません。

**実装の位置**

- core.js：純粋な日時・検証・繰り返し・集計・テンプレート・ICS処理。
- storage.js：保存トランザクション、移行、復旧、Undo、通知の重複抑止。
- notifications.js：ページ内通知予約、再検証、表示。
- app.js：画面と操作。名前はDOMのtextContentで表示します。
- styles.css：同梱のCSS。レスポンシブ、拡大、印刷、配色、文字サイズ。
- ds-sw.js：オフライン・更新・通知からの移動。
- tests：Nodeのテストランナー。保存APIにはfake-indexeddb、DOMにはlinkedomを使用。これらは開発時のみの依存です。

**公開前に実機で確認すること**

現環境には操作できるブラウザーが接続されていないため、実画面の配置とネイティブUIは未検証です。PCのChrome/Edge、iPhoneのSafariとホーム画面アプリ、AndroidのChromeで以下を確認してください。

1. 初回の旧データ移行、再起動後の保存、JSON書出・復元、別タブ編集。
2. 320px程度の幅、スマートフォンのキーボード表示、画面回転、200%拡大。
3. Tab・Enter・Escape、モーダルのフォーカス復帰、読み上げ、長い名前。
4. 通知の許可・拒否・テスト・00:00開始・タブ復帰・複数タブ。
5. 初回オンライン→オフライン再起動、旧SWからの更新、更新中の下書き保持。
6. 印刷・PDF・SVG・ICSの受け取り先での確認。

公開する変更ではcore.jsとds-sw.jsのVERSION、HTML/SW/app.jsの資産クエリー、package.jsonのバージョン表示を一緒に更新し、テストを実行してください。アプリのロールバック時にもIndexedDBは保持します。保存形式を変更する版には別途前方移行を実装し、旧版で新しい形式を上書きさせないでください。
