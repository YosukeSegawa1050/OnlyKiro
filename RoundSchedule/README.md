**Daily Schedule 2.2.1**

24時間の円グラフと予定一覧を組み合わせたスケジューラーです。端末内保存に加え、認証付きの共有サーバーとChatGPT用MCP接続を利用できます。ブラウザー側のJavaScript・フォント・CSSを外部CDNから読み込むことはありません。共有サーバーは公式MCP SDKを使用します。

2.2.1では、古い画面を「最新」と誤判定する更新処理を修正しました。配信中の版・動作中のService Worker・画面の版を照合し、画面だけ古い場合も再読込します。更新専用の救済ページも追加しています。

**ChatGPTとの共有**

初期設定は `npm.cmd run setup:shared`、共有サーバー起動は `npm.cmd run start:shared` です。アプリの「ChatGPT連携」からログインし、端末の予定を共有先へ取り込めます。起動手順・公開時の設定・ChatGPTへの登録は [CHATGPT_CONNECTION.md](CHATGPT_CONNECTION.md) にまとめています。公開先未定のため、外部へのデプロイと実ChatGPTアカウントでの登録は未実施です。

**起動・検証**

Node.js 24で検証しています。プロジェクトのディレクトリーで以下を実行します。Windows PowerShellでnpm.ps1が制限されている場合はnpm.cmdを使います。

```text
npm.cmd ci --ignore-scripts
npm.cmd run check
npm.cmd run format:check
npm.cmd test
npm.cmd run build
npm.cmd start
```

ブラウザーで http://127.0.0.1:8765/RoundSchedule.html を開きます。終了は起動したターミナルでCtrl+C。ファイルを直接ダブルクリックする方法は、PWA・通知・保存の動作を揃えられないため検証対象外です。

端末保存版はHTTPSでdistの静的ファイルを配信します。buildは必要な19ファイルだけをdistへコピーします。vercel.jsonのルート書き換えを維持し、buildCommandとoutputDirectoryを指定しています。共有版にはNodeサーバーと永続ディスクが必要です。どちらのサーバーもプロダクトのファイルだけを配信し、テスト・依存ファイル・認証設定・保存ファイルを公開しません。

**更新が反映されないとき**

「更新確認」で古い版を「最新」と表示する場合は、同じサイトの `/update.html` を開きます。ローカル起動の例は http://127.0.0.1:8765/update.html です。更新後に予定表へ戻ります。失敗した場合は「もう一度確認」で再試行できます。

同じスキーム・ホスト・ポートで開いてください。更新処理はIndexedDB・localStorageの予定データを削除しません。別のURLへ移動したり、ブラウザーのサイトデータを消したりする必要はありません。

**カテゴリーとデータ操作**

- カテゴリーを1.5秒長押しすると、項目が揺れて並べ替えモードになります。ドラッグで移動し、一覧の上下端では自動スクロールします。「完了」・一覧外の余白・Escapeで終了でき、「完了」は長い一覧でも表示されます。
- ダブルタップまたはダブルクリックで名前・色を編集します。「＋」は新しいカテゴリーの追加です。
- キーボードではカテゴリーにフォーカスしてSpaceで並べ替え開始、上下矢印で移動、EnterまたはEscapeで終了します。通常時のEnter・F2は編集を開きます。
- 並べ替えは移動ごとに保存します。保存失敗時は元の順序へ戻し、別画面で順序が変わっていた場合は上書きを拒否します。
- 「設定・データ」でJSON・ICS・SVGを選び、「保存」または「読込」を使います。日付範囲はICS選択時だけ表示され、SVGは保存専用です。
- 移行・復旧前のデータ、インストール、オフライン状態は「その他」にまとめています。「ChatGPT連携」の接続URL・手順と端末内保存への切替も、必要なときに開けます。

**日時と予定の仕様**

- 予定は開始日・開始時刻・終了日・終了時刻を持ちます。23:00〜翌06:00は終了日を翌日に指定します。
- 表示・重複・集計・繰り返しは同じ日時処理を使います。日をまたぐ予定は各日の範囲へ切り取って表示し、一覧には継続であることを示します。
- 区間は開始を含み終了を含みません。09:00〜10:00と10:00〜11:00は重複しません。
- 時間指定予定は7日以内。開始と終了が同じ日時の予定は登録しません。
- 終日は開始日〜終了日を両端含みます。時刻未定は開始日だけに表示します。終日・時刻未定は時間指定予定を妨げない情報として扱います。
- 完了した時間指定予定も一日の時間を使ったものとして集計。中止予定は時間の占有と通知の対象外です。
- 繰り返しは曜日指定、終了日を含む1年以内。この回のみの変更は元のシリーズへ除外日を追加し、単発予定を作成します。全体の変更は最初の開始日から適用します。
- テンプレートには対象日に開始する予定を保存します。前日からの持ち越しは含みません。置換時も前日開始の予定は残し、衝突時には全体を適用せずエラーにします。
- 端末保存版の時刻は端末の現地時刻です。共有版は設定したタイムゾーンを使い、端末と異なる場合は閲覧のみになります。夏時間の欠落・重複時刻の専用UIは未対応です。

**保存と移行**

- 新しい保存先はIndexedDBのdaily-schedule-v2です。読込・競合確認・書込・取り消し用退避を同じトランザクションで行います。
- localStorageのdaily_schedule_dataがある場合、初回だけ検証して移行します。旧データの原文を退避し、元のlocalStorageは削除しません。旧データに日付がなければ移行日を割り当て、結果を永続化します。
- 構造が壊れたデータは黙って初期化しません。原文の保存、正常項目の確認付き復旧、JSONバックアップからの復旧を案内します。
- JSON復元は件数を表示して確認後に実行。直前の全データを別途退避し、「元に戻す」も用意します。
- 端末保存のUndoは直前の保存操作1回分、共有先は最大30操作を保持します。別画面・ChatGPTからの未確認の更新がある場合は拒否します。
- 編集中の予定・カテゴリー・テンプレートが別タブで変更された場合、古い編集で上書きせず入力を保持して知らせます。
- 予定の下書きはsessionStorageに保存します。同じタブでの再読込・閉じた編集画面からの復帰に対応し、7日以内の下書きを復元できます。ブラウザー全体の終了後までの保持は保証しません。
- 移行後は旧バージョンのタブを閉じてください。旧タブでlocalStorageが更新された場合は案内を表示します。IndexedDBのデータを旧版へ自動的に戻す処理はありません。
- ブラウザーの全データ削除に備え、ダウンロードしたJSONを別の場所に保管してください。端末保存モードは同期しません。共有モードでは同じサーバーへログインした端末間で同期します。

**通知・オフライン・出力**

- 通知は明示的な操作で許可し、設定を保存して有効化します。開始時・1/5/10/15/30/60分前を全体設定で選択できます。予定ごとの上書きもあります。
- 発火時刻は秒を含む絶対時刻で計算し、日付境界にも対応。通知済みキーをIndexedDBで取得してタブ間の重複を抑えます。失敗時は再試行できるようキーを戻します。
- アプリ終了後の予約実行やバックグラウンドでの定刻配信は保証しません。遅れた通知は1分以内のものだけを扱います。Web Push配信サーバーは未実装です。
- モバイルではService WorkerのshowNotificationを優先します。通知を選ぶと該当日の予定を開き、他の編集中の画面を移動させません。
- SWはバージョン単位でHTML/CSS/JSをまとめて事前保存し、その組み合わせで起動します。キャッシュ済みなら低速回線や503でもネットワークを待ちません。
- 更新確認は `release.json` を `no-store` で取得し、動作中のSWの `GET_VERSION` 応答と画面の版を照合します。配信情報と一致するまで「最新」とは表示しません。
- 取得済みの待機中SWはオフラインでも適用できます。通信・インストール・有効化の待機には期限を設け、失敗時は再試行できます。通常の更新では下書きを保存してから再読込します。
- `release.json` と救済ページはSWのキャッシュ対象外です。他アプリのキャッシュを削除したり、他アプリのページ遷移を置き換えたりしません。
- ICS出力は指定した1年以内の期間の繰り返しを単発予定に展開します。ICS入力は単発VEVENT、分単位の日時ありまたは終日、現地時刻またはUTCに対応。RRULE、RECURRENCE-ID、EXDATE、TZIDや秒単位の時刻を含む入力は説明付きで拒否します。
- SVG画像として一日を保存できます。印刷ボタンからブラウザーの「PDFに保存」も利用できます。Google/Apple等のカレンダーとの双方向同期ではありません。

**実装の位置**

- core.js：純粋な日時・検証・繰り返し・集計・テンプレート・ICS処理。
- storage.js：保存トランザクション、移行、復旧、Undo、通知の重複抑止。
- shared-storage.js / shared-ui.js：共有保存・ログイン・接続設定・許可解除。
- server：SQLite保存、OAuth認証、共有API、ChatGPT用MCP。
- notifications.js：ページ内通知予約、再検証、表示。
- category-interactions.js：カテゴリーの長押し・ドラッグ・ダブルタップ・キーボード操作。
- app.js：画面と操作。名前はDOMのtextContentで表示します。
- styles.css：同梱のCSS。レスポンシブ、拡大、印刷、配色、文字サイズ。
- ds-sw.js：オフライン・更新・通知からの移動。
- updates.js：配信版とSW版の照合、待機中更新の適用、時間制限と再試行。
- release.json / update.html / update-page.js：配信中の版情報、同じサイトから開く更新専用ページ。
- tests：Nodeのテストランナー。保存APIにはfake-indexeddb、DOMにはlinkedomを使用。これらは開発時のみの依存です。

**公開前に実機で確認すること**

2.2.1では自動テスト169件、構文・整形・19資産のビルドが成功しました。Chromeで旧画面からの更新、複数タブに残った古い画面の更新、救済ページ、保存予定・下書きの保持、オフライン失敗時に「最新」と誤表示しないことを確認しました。2.2.0では幅320・390・820・1200pxの基本画面・共有操作と、カテゴリーのタッチ操作・上下端自動スクロール・多数項目の移動保存・「完了」ボタンの表示も検証しています。iPhone/Androidの実機、OS通知、公開HTTPS環境、実ChatGPT内の登録は未確認です。公開時には以下を確認してください。

1. 初回の旧データ移行、再起動後の保存、JSON書出・復元、別タブ編集。
2. 320px程度の幅、スマートフォンのキーボード表示、画面回転、200%拡大。
3. Tab・Enter・Escape、モーダルのフォーカス復帰、読み上げ、長い名前。カテゴリーの長押し・ドラッグ・ダブルタップ、Space・上下矢印・F2での操作。
4. 通知の許可・拒否・テスト・00:00開始・タブ復帰・複数タブ。
5. 初回オンライン→オフライン再起動、旧SWからの更新、複数タブに残った古い画面、待機中更新のオフライン適用、更新中の下書き保持、救済ページからの復帰。
6. 印刷・PDF・SVG・ICSの受け取り先での確認。

公開する変更ではcore.jsとds-sw.jsのVERSION、release.json、HTML/SW/app.js/更新専用ページの資産クエリー、package.jsonとpackage-lock.jsonのアプリ版を揃えてテストしてください。配信時はrelease.jsonと更新専用ページをキャッシュしない設定も維持します。アプリのロールバック時にもIndexedDBは保持します。保存形式を変更する版には別途前方移行を実装し、旧版で新しい形式を上書きさせないでください。
